Case Study

当 AI 开始设计
判断必须可以追溯

我 0–1 搭建了一套可治理的 Design Agent 工作流：将散落在 Figma 中的设计经验提取成可追溯、可复用、可校验的设计知识，再通过阶段化决策、组件合同、token 约束和质量检查，约束 Creator 生成符合金融业务、品牌和设计系统规范的 UI 与前端代码。

Context

AI 已经可以生成看起来像样的 UI。但在真实业务设计里，生成一个“像”的页面并不够，需要同时满足业务逻辑、品牌规范、组件体系、页面范式、交互状态和移动端可用性要求。如果让 AI 从需求直接生成最终页面，输出很容易出现结构不稳定、组件复用不清晰、状态缺失或信息层级不符合业务判断的问题。

因此，此项目真正要解决的问题是：

如何让 AI 生成依赖可追溯的设计知识和明确的决策边界，而不是依赖模型记忆和自由发挥？

Workflow Before

设计知识存在于历史页面和稿件中，即使有 AI 辅助生成，也需要每次从头理解。在需求落地过程中，产品和设计需要反复对齐、澄清需求，前端需要解读设计稿并自行判断复用逻辑。需求、设计规范、页面参考和代码实现分散在人、Figma 和沟通记录里。

System Strategy

我设计了一个三层的系统：Extractor 从 Figma 资产中提取设计范式；KB 沉淀结构化知识并显化不确定性；Creator 在知识和约束下生成 UI 与代码。让 AI 生成不再是黑盒——设计知识从哪里来、如何被复用、哪里存在不确定性，都可以被定位和检查。

Deep Dive 01

Turning Design Assets into Governed Knowledge Governed Knowledge

设计资产里包含大量隐性知识：设计变量、组件结构、布局规则、页面模式。Extractor 的目标是把这些资产转成 Agent 可消费的知识层，KB 则通过 schema 约束结构、source mapping 保留来源、confidence 显化不确定性，并将需要人工判断的内容进入 review queue——让设计知识具备治理能力。

Deep Dive 02

Designing the Creator as a Constrained Generator Constrained Creator

Creator 不是一个自由发挥的 UI 生成器，而是一个受范式约束的金融 UI 生成 Agent。它的核心不是“直接画页面”，而是按阶段消费 KB，并把业务理解、交互决策和设计生产分开处理。

Key Design Decisions

系统层关键设计决策

01

解耦流程

拆分抽取与生成

将“提取已有设计资产”和“生成新页面”拆成两个 Agent。提取需要忠实保留和结构化，生成需要组合和扩展。拆开之后，质量问题可以被定位到提取、知识结构或生成消费环节，而不是全部混在一次生成结果里。

02

沉淀知识库

KB 作为可治理的中间层

KB 不是临时缓存，而是系统的设计知识中间层。它保存 tokens、components、guidelines、page patterns、source references ，并评估置信度confidence，让设计知识可以被追溯、检查、修正和复用

03

降低模型静默

让不确定性可检查

AI 在提取和归纳设计范式时不可避免会遇到不确定判断。系统通过 confidence 和 review queue 显化这些不确定性，让需要人工判断的内容进入审查队列，而不是由模型静默决定。

04

映射组件并自检

用 workflow 约束生成

Creator 是这套系统的下游执行层。通过阶段化 workflow、组件来源映射、token 约束和自检机制消费 KB，让生成结果依赖明确的设计知识和决策边界。

Result

我完成了 Extractor Agent → Governed KB → Creator Agent 的 0–1 工作流搭建。Extractor 能力与 KB schema 被事业群 AI 设计提效平台完整采纳，用于提升 AI 设计生成的稳定性、复用性和质量可控性。Creator 作为生成约束层，验证了设计知识如何被下游消费，以及如何通过阶段化决策和质量检查减少输出漂移。

Reflection

在 AI 参与设计生产后，信息损失是设计师的责任，不是算法的副产品。设计师需要定义哪些信息必须被保留、哪些规则应该进入知识层、哪些判断必须被人审查。
